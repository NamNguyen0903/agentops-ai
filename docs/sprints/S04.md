## 1. Authority and objective

Sources: [PRD v0.2](../product/PRD.md), [architecture v1.1](../architecture/overview.md), [ADR-0001](../adr/0001-architecture.md), [ADR-0002](../adr/0002-authentication.md), [ADR-0003](../adr/0003-async-execution-and-recovery.md), [proposed ADR-0004](../adr/0004-langgraph-state-and-agent-boundaries.md), [S03 closeout](S03_CLOSEOUT.md), and [AGENTS.md](../../AGENTS.md).

Deliver a **single-agent, deterministic, offline LangGraph baseline** under the existing modular monolith. Demonstrate typed state, one bounded graph path, validated result proposal and fail-closed error handling without pretending the full FR-008 Planner/Research/Writer workflow is complete. This sprint is an incremental engineering milestone, not the end-to-end MVP.

## 2. Scope

**In:** graph state and version metadata; exactly one fixture-backed execution node and explicit termination; application-owned input/output validation; injected deterministic adapter; bounded graph invocation under offline tests; safe errors; unit and narrowly scoped integration tests; dependency security review and reproducible lockfile updates after approval; documentation and CI evidence.

**Out:** live Bedrock/LLM or search; autonomous web tools; multi-node Planner/Research/Writer (S05); real retrieval, evidence persistence and citation grounding (S06); queue claiming, execution attempts, leases, recovery and worker activation (ADR-0003 pending/S07); reporting APIs and publication; production deployments, real users, live authentication, state-machine or schema migrations unless separately authorized.

**Non-claims:** an offline graph returning a candidate is not a completed ResearchTask. Do not change an accepted `queued` task to `running` or any terminal state through this graph. Existing S03 API and UI continue their verified behavior.

## 5. Approved Development MVP technical boundaries

- Application service validates submitted research inputs and injects immutable policy/fixture dependencies. Tool permissions are code-owned, never read from graph state.
- Graph state is ephemeral; no checkpointer for this baseline. Do not mistake checkpoints for PostgreSQL admission, attempt fencing, or durable recovery.
- One deterministic node with START → fixture node → END is sufficient for S04; full PRD graph remains S05/S06 work.
- Output is an unpublished `GraphResult` proposal and cannot itself change task status. Missing supporting evidence is not silently treated as a publishable report.
- Budgets are application-owned. PRD initial hypotheses (180s running, 8 model calls, 40,000 tokens, 1 malformed-output repair, etc.) are **not validated performance claims**; offline fixture test should enforce a smaller explicit per-invocation ceiling without weakening the product limits.

## 6. Verification/evidence policy

For every check record source SHA, date/environment, exact command, exit code, result, skips, residual risk and evidence origin. Reuse unchanged S02/S03 PASS history. Run only relevant new/affected tests. Do not claim backend lint/type-check PASS (currently NOT_CONFIGURED). If dependencies change, follow [dependency policy](../development/PYTHON_DEPENDENCIES.md) and review all applicable lockfiles/advisories without disabling hash enforcement. No live calls or shared DB migrations.

## 7. Security and release carry-forwards

- Authentication disabled by default; ADR-0002 accepted **Development MVP only**; no live Google login, real users or deployment.
- Stock Authlib PKCE DEBUG exposure: **KNOWN FAIL**, strict XFAIL and bounded mitigation preserved.
- ADR-0003 **PARTIALLY ACCEPTED for admission only**; no worker/lease/recovery inference.
- S02 release gates remain mandatory; crash recovery/backup-restore and real-user security controls unverified.
- Preserve a single canonical worktree, existing backup stash and historical testing evidence; owner performs commit/push/merge; no unauthorized release.
