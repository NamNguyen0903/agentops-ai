bounded, deterministic, offline workflow containing

### 4.1 Logical workflow

Validated Input -> Planner -> Research
-> Evidence Validation -> Writer
-> Report Validation -> Non-publishable Outcome.

Evidence Validation may route to explicit abstention
when fixture evidence is insufficient.

Planner and Writer may use the same globally bounded
repair allowance for eligible malformed output.

Every execution stage may fail closed.

Application-owned routing must prevent unapproved
nodes, dynamic tool permissions and unbounded loops.

## 5. Execution policy

| Control | Owner-approved policy |
|---|---|
| Maximum subquestions | 4 |
| Global repair attempts | Maximum 1 |
| Specialized adapter invocations | Maximum 4 |
| Initial LangGraph recursion limit | 12 |
| Soft execution deadline | 30 seconds |
| Live model calls | 0 |
| Live search calls | 0 |
| Live retrieval calls | 0 |
| Live provider tokens | 0 |
| Paid inference cost | USD 0 |
| Durable checkpoints | 0 |
| Publication permission | False |

The recursion limit of 12 is an approved initial
engineering value requiring actual LangGraph tests.

Graph recursion steps and adapter invocation counters
are distinct controls.

Check deadlines at graph entry, before and after each
node and repair invocation, and before outcome acceptance.

A caller cannot extend the application-owned deadline.

The soft deadline cannot forcibly interrupt a blocked
node. No hard-timeout guarantee is claimed.

Application code owns all execution counters,
routing decisions, policy limits and repair allocation.

## 6. Global repair policy

- Planner malformed output may receive one eligible repair.
- Writer malformed output may receive one eligible repair
  only if the global allowance remains unused.
- A repair consumes the same global execution budgets.
- Repeated malformed output fails closed.
- No implicit retries are allowed.
- Security violations fail closed immediately.
- Unauthorized state mutations fail closed immediately.
- Unknown or cross-task fixture references fail closed.
- Expired deadlines do not permit repair.
- Insufficient evidence produces explicit abstention.

Adapters cannot grant repair allowances, increase budgets,
modify permissions or select arbitrary tools.

### Input and context boundaries

Preserve the S04 question bound of 4000 characters,
the 8192-byte scope bound and maximum JSON depth of 5.

Reject whitespace-only questions, non-finite numbers,
unknown fields, unsupported JSON values and invalid types.

Use UUID task identity and optional UUID attempt identity.

canonical scope, version metadata and execution policy.

Mutable nested values must not alias trusted context.
Frozen Pydantic configuration alone is not sufficient.

unvalidated model construction, model-copy updates or
mutable nested input structures.

- Maximum four subquestions.

Counters and limits must remain distinct.

enforcement belongs to WP03-WP04.

### Fixture adapters

not arbitrary graph state updates.

one specialized adapter invocation.

Fixtures are application-owned synthetic records,
not real externally collected evidence.

task association, optional attempt association and
fixture version.

Separate fixture coverage from real evidence coverage.

receive its complete graph-boundary verification in WP04.

### Threat model and trust boundaries

Treat request data, fixture content, adapter
outputs, node updates and unexpected exceptions
as untrusted at their respective boundaries.

Application-owned context, permissions, routing,
deadlines, counters and repair allocation must
not be controlled by adapters or graph output.

Target threats include:

- Fabricated, unknown and cross-task references.
- Mixed malformed and security-sensitive output.
- Unauthorized mutation of protected context.
- Unknown or unauthorized state update channels.
- Nested terminal-result type and shape corruption.
- Exception category spoofing and sensitive errors.
- Repeated repair and invocation-budget bypass.
- Deadline extension and expired execution.
- Forbidden network, DNS and database operations.
- Lifecycle mutation and report publication.

The scope is deterministic offline execution.
No arbitrary-code sandbox, hard timeout, real
retrieval security or production certification
is claimed.

### Guard architecture

Preserve the six existing graph nodes:

Planner, Research, Evidence Validation, Writer,
Report Validation and Outcome.

Use application-owned execution guards at graph
entry, adapter calls, node boundaries, routing
and independent terminal verification.

Controller state is private to one invocation.
Do not share mutable execution counters between
requests or expose the controller to adapters.

No new agent, service, worker process or durable
checkpoint is introduced.

### Error classification and repair eligibility

Security-sensitive fields must be checked before
an output is classified as eligible for repair.

If safe inspection is not possible, fail closed
without granting repair.

Only explicitly validated malformed Planner or
Writer outputs may be eligible.

Unknown exceptions map to sanitized execution
failure. Do not read arbitrary exception category
properties or expose raw exception messages.

Security violations, unauthorized mutation,
unknown references, deadlines, exhausted budgets
and unexpected exceptions never grant repair.

Valid incomplete fixture evidence produces
abstention rather than repair.

No automatic LangGraph retry policy is allowed.

### Application-owned accounting

Reserve every adapter invocation before calling
the adapter. Failed calls consume the budget.

A repair consumes one invocation and the single
shared global repair allowance.

Expected successful execution accounting:

| Path | Adapter calls | Repairs |
|---|---:|---:|
| Normal candidate | 3 | 0 |
| Planner-repaired candidate | 4 | 1 |
| Writer-repaired candidate | 4 | 1 |
| Normal abstention | 2 | 0 |
| Abstention after Planner repair | 3 | 1 |

Reject a fifth invocation before executing it.

Reject a second repair regardless of whether
the first repair was attempted by Planner or Writer.

Counters in graph state and final results must
agree with application-owned execution accounting.

Counter snapshots must not be accepted from
untrusted adapters.

### Deadline enforcement

Use an application-owned monotonic clock.

The default soft deadline is 30 seconds.

A caller may shorten but never extend the
application-owned deadline.

Check the deadline at graph entry, before and
after every node, before and after repair
invocations, and before accepting the outcome.

Check adapter failure paths as well.

An expired execution cannot start another
adapter, repair, downstream node or accept a result.

Deadline expiry cannot forcibly interrupt a
blocked synchronous node.

Graph recursion steps and adapter invocations
are separate controls.

Preserve the approved initial recursion limit
of 12 and verify actual repaired execution paths.

### Node update ownership

Baseline normal-path update channels:

| Node | Required output channels |
|---|---|
| Planner | plan, stage, counters |
| Research | research_output, fixture_coverage, stage, counters |
| Evidence Validation | research_output, fixture_coverage, stage |
| Writer | draft_report, stage, counters |
| Report Validation | draft_report, stage |
| Outcome | result, stage |

Check exact output shape before LangGraph merge.
Reject unknown channels, missing required
channels and unauthorized state changes.

The execution controller owns repair_used
and authoritative counters.

Any repair-specific channel changes must have
explicit application-owned rules and tests.

Do not treat a node's declared output permission
as proof that its output is trusted.

### Terminal integrity

Validate exact raw types and expected model
shapes recursively before accepting a result.

Reconstruct the expected result independently
from verified graph state and trusted context.

Do not rely solely on Pydantic normalization,
ordinary dictionary equality or serialization.

Preserve UUID identities, strict scalar types,
fixture provenance and non-publishable outcomes.

Real evidence coverage remains zero.
Synthetic fixture coverage remains distinct.
