## 2026-11-23 — SEC-10 Session Rotation Security Checkpoint

**Sprint:** S02 — IN_PROGRESS / PARTIALLY_VERIFIED

**Ticket:** AG-003.6 — READY_FOR_TECH_LEAD_REVIEW

**Security finding:** SEC-10 — Cross-user session revocation during account switching

**Architecture:** ADR-0002 PROPOSED

**Authentication:** IMPLEMENTED_FOR_REVIEW — disabled by default

### 1. Finding and root cause

During Google OIDC callback, the backend passes the existing
browser session cookie to `AuthService.login()` as `old_token`.

Previously, `AuthService.login()` revoked the old session using
only `AuthSession.token_digest`, without checking ownership.

Consequently, a successful login to account B could revoke an
existing session belonging to account A.

This behavior represented an undefined account-switching policy
and an unnecessary cross-user session side effect.

No remote exploit or confirmed production incident was observed.

### 2. Remediation

Updated:

`apps/api/src/agentops_api/services/auth.py`

The old-session revocation UPDATE now requires:

- Matching token digest.
- Matching authenticated `user.id`.
- A session that has not already been revoked.

The new behavior is:

1. Login again as account A with A's existing token:
   revoke A's old session and create a new one.
2. Login as account B while presenting A's existing token:
   create a new B session without revoking A's session.
3. An unknown or unrelated old token:
   do not revoke another user's session.

The change preserves the SEC-07 lock ordering policy:
User before AuthSession.

### 3. PostgreSQL regression coverage

Updated:

`apps/api/tests/test_auth_postgres.py`

The existing `test_postgres_session_contract()` now includes
SEC-10 regression assertions covering:

- Two independently provisioned users.
- Cross-user account switching.
- Preservation of account A's previous session.
- Successful authentication of account B.
- Same-user session rotation.
- Rejection of B's revoked old session.
- Cleanup of both disposable test users.

The regression uses the existing disposable PostgreSQL
integration environment, not the development database.
