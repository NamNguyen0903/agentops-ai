## 4. AG-003.1 — Database & Authentication Architecture

### Objective

Define and review the database and identity architecture before implementing security-sensitive backend functionality.

### Proposed Architecture

| Component | Proposed approach |
|---|---|
| Database | PostgreSQL |
| ORM | SQLAlchemy 2.x |
| Migrations | Alembic |
| Database driver | Psycopg 3 |
| Internal user ID | UUID |
| Identity model | `users` + `auth_identities` |
| Local credentials | Separate credential model |
| Browser authentication | HttpOnly cookie |
| Session model | PostgreSQL-backed opaque sessions |
| Password hashing | Argon2id |
| CSRF | Origin validation plus session-aware CSRF protection |
| Authorization | Backend owner-scoped enforcement |
| Authentication library | FastAPI Users — conditional candidate |
| Authentication fallback | Authlib + approved OIDC provider |

These choices are proposals, not approved dependencies or implemented features.

### Architecture Documents

- `docs/product/PRD.md`
- `docs/architecture/overview.md`
- `docs/adr/0001-architecture.md`
- `docs/adr/0002-authentication.md`
- `AGENTS.md`

## 11. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Authentication library maintenance limitations | Review support, compatibility and fallback before implementation |
| Incompatible session persistence model | Validate framework extension points before migrations |
| Credential leakage | Separate secrets from Git and redact logs |
| CSRF vulnerabilities | CSRF proof plus Origin validation |
| Broken access control | Enforce authorization in backend services and queries |
| Database migration failure | Review migrations and test against PostgreSQL |
| Session state loss | Use persistent server-side session storage |
| Docker regressions | Rerun existing S01 smoke tests |
| Scope creep | Restrict S02 to persistence and authentication |
| False verification claims | Separate reported results from inspected evidence |
